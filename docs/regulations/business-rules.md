# 業務規則（R-xx）

> Story 驗收條件與測試都引用這裡的編號。數值來源：2026-11-25 人的決定（見 `docs/decisions.md`），
> 標示「假設」的條目尚待人確認，確認前程式依假設實作。

| 編號 | 規則 | 來源 |
|---|---|---|
| R-01 | 幣別固定新台幣 `TWD`；金額一律以**整數「元」**儲存與傳遞（禁止 float），前端只負責格式化顯示 | 假設 A-01 |
| R-02 | 商品標價已含稅，不另外計稅 | 假設 A-02 |
| R-03 | 運費：**折扣後**商品金額 ≥ 1000 元免運，否則運費 60 元 | 人決定（門檻計算基準為假設 A-03） |
| R-04 | 訪客可瀏覽商品；加入購物車、結帳、查訂單**必須登入** | 人決定 |
| R-05 | 購物車單一商品數量 1–99，且不得超過目前庫存；結帳時再檢查一次 | 假設 A-04 |
| R-06 | 建立訂單時，扣庫存與建立訂單在**同一個交易**；任一商品庫存不足 → 整筆失敗（409 `ORDER_OUT_OF_STOCK`），不會只扣一部分 | AGENTS.md 6.3 |
| R-07 | 訂單明細保存下單當下的商品名稱與單價（價格快照），之後商品改價不影響舊訂單 | AGENTS.md 6.3 |
| R-08 | 訂單狀態機：`pending_payment → paid → shipped → completed`；`pending_payment → cancelled`。其他轉換一律拒絕（409 `ORDER_INVALID_TRANSITION`） | AGENTS.md 6.3 |
| R-09 | 只有「待付款」訂單可以取消（會員本人或管理員）；取消時回補庫存，並歸還優惠券使用次數 | 假設 A-05 |
| R-10 | 付款使用**模擬金流**：不收、不存信用卡號；只存交易編號與狀態；金流回呼必須通過 HMAC-SHA256 簽章驗證；同一交易編號重複回呼只處理一次 | 人決定 |
| R-11 | `POST /orders` 與 `POST /orders/{id}/payments` 必須帶 `Idempotency-Key` 標頭；同一會員重複送出同一個 Key → 回傳第一次的結果，不重複下單／付款 | AGENTS.md 4 |
| R-12 | 優惠券：類型 `fixed`（折固定金額）或 `percent`（打折，1–90%，須設單筆折抵上限 `max_discount`）；有最低消費 `min_spend`、有效期間、總使用次數上限；**每位會員每張限用一次**；**一筆訂單最多一張（不可疊加）**；折扣不得超過商品小計；**不折運費** | 人決定做優惠券；細則為假設 A-06 |
| R-13 | 會員只能讀寫自己的購物車、地址、訂單；讀取別人的資源一律回 404（不透露資源是否存在） | AGENTS.md 6.3 |
| R-14 | 只有管理員（admin）可以新增／修改商品與庫存、將訂單改為已出貨／已完成 | AGENTS.md 6.2 |
| R-15 | 限速：同一 IP＋帳號登入失敗 5 次／5 分鐘 → 429；下單與優惠券試算每位會員 20 次／分鐘 | 假設 A-07 |
| R-16 | 密碼至少 8 字元，使用 argon2 雜湊；Email 不分大小寫且不可重複 | AGENTS.md 5.3 |
| R-17 | 登入狀態用 httpOnly Cookie（SameSite=Lax，正式環境加 Secure），有效 7 天；會改變狀態的請求必須帶 CSRF token | AGENTS.md 5.3 |
| R-18 | 列表分頁 `page_size` 上限 50；排序只接受白名單 `newest`、`price_asc`、`price_desc`、`name` | AGENTS.md 4 |
